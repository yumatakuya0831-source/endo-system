# 開発エージェント共通ルール

このリポジトリで作業する人およびAIエージェントは、リポジトリルートの `development-rules.md` を規範文書として扱う。別の場所へ配置する場合は、この参照先も同じ変更で更新する。

## 作業開始前

1. ユーザーの最新指示、承認済み要件、設計、進捗、テスト結果の順に確認する。
2. 対象要件IDと受入条件を特定する。対応する要件がなければ実装を始めない。
3. 情報不足、文書間の矛盾、破壊的変更、セキュリティまたはデータ損失の懸念がある場合は、影響と選択肢を示して確認する。
4. 小さくレビュー可能な作業単位と検証方法を決める。

## 作業中

- 承認済みのスコープを越える機能を追加しない。
- 認可を画面の表示制御だけに依存させない。サーバーおよびデータ層でも検証する。
- 外部入力、環境変数、秘密情報、個人情報を信頼しない。
- 変更理由、変更ファイル、判断、未解決事項、検証結果を進捗文書へ残す。
- 仕様変更が必要になった場合は、コードだけを先行変更せず要件と設計を先に更新する。

## 作業完了時

1. 受入条件に対応するテストを実施する。
2. 静的解析、型検査、単体・結合テスト、ビルドなど、リポジトリで利用可能な品質検査を実行する。
3. 実行していない検査は「未実施」とし、成功したと表現しない。
4. 実施内容、証拠、残課題、リスク、次の作業、完了判断を引き継ぐ。

## 優先順位

指示が競合する場合は、ユーザーの最新の明示指示、承認済み要件、承認済み設計、`development-rules.md`(規範文書)、本書(AGENTS.md)、その他参考資料の順に優先する。法令・安全・セキュリティ上の制約は常に守る。
